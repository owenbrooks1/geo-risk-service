## Files

### 1. `pyproject.toml` (already exists, untracked): add config only
- `[build-system]` using `uv_build`, uv's own build backend. This is what lets `import geo_risk_service` work from tests and, later, from `uvicorn`. It is needed only to install the project. It adds no runtime code. **It counts as a new build-time dependency, so approving this plan approves it.** The alternative is to point pytest at `src/` with no build backend. That works for tests but makes running the app later more awkward.
- `[tool.ruff]`: `target-version = "py312"`. Rules: `E`, `F` (errors and undefined names), `I` (import order), `B` (common bug patterns) and `UP` (modern syntax). Default line length.
- `[tool.pytest.ini_options]`: `testpaths = ["tests"]`, `addopts = "-ra --strict-markers"`.
- `uv.lock` is regenerated by `uv sync` if needed and committed with it.

### 2. `src/geo_risk_service/__init__.py`
- One-line module docstring only. This is the smallest possible package. The contracts stage sets the real layout and then updates the "Exact paths" note in `docs/components.md`.

### 3. `tests/test_package.py`
- `test_package_imports`: imports `geo_risk_service` and checks that it loaded from this repo's `src/`.
- Docstring, stated honestly: "Harness check. Proves that `make verify` runs real tests against the installed package. It does not cover any AC or INV rule."

### 4. `Makefile`
```make
.PHONY: verify
verify:
	uv run --locked ruff check .
	uv run --locked ruff format --check .
	uv run --locked pytest
```
- `--locked` makes the check fail if `uv.lock` is out of step with `pyproject.toml`. This stops dependencies drifting without anyone noticing.

### 5. `.github/workflows/verify.yml` (CI)
- Runs on every push and pull request, on `ubuntu-latest`.
- Steps: check out the code, install uv (`astral-sh/setup-uv`), `uv sync --locked`, then `make verify`.
- CI needs network access to download packages. That is consistent with INV-2, which covers the product and its tests, not the build machine.
- It only runs once the commit is pushed. Pushing needs owner approval.

### 6. Commit gate: `.claude/hooks/verify_before_commit.py` plus a `hooks` entry in `.claude/settings.json`
- This is a `PreToolUse` hook on `Bash`, meaning a script Claude Code runs before every shell command the agent issues. The script reads the command. If the command is a `git commit`, it runs `make verify`. On failure it exits with code 2, which blocks the commit and shows the agent the failure output. Any other command passes straight through.
- The script uses only the Python standard library and is run with `uv run --no-project python`, so it does not need `jq` or any other extra tool.
- **Known gap:** this gates commits made by the agent only. A commit the owner makes in their own terminal is not gated. CI is the backstop for that.
- This changes a harness file. It is allowed because this is the lead session on `main` and the owner has approved it.
